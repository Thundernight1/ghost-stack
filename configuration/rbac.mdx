---
title: "RBAC hierarchy"
description: "Map organizational tiers to kernel-enforced UID ranges across the four Ghost-Stack RBAC levels."
---

Ghost-Stack enforces a four-tier RBAC hierarchy through Linux user namespaces. Each tier maps to a UID range; the kernel scheduler enforces the boundary. There is no userspace policy engine that can be bypassed.

## Tiers

```
TierRoot      --  Full system visibility across all namespaces
TierDirector  --  Read access to all subordinate container data
TierManager   --  Own department + direct reports only
TierStaff     --  Own container only; zero upward visibility
```

| Tier | UID range | Typical use |
|---|---|---|
| `ROOT` | reserved | Orchestrator and host operators |
| `DIRECTOR` | 100000 – 199999 | Cross-department incident response |
| `MANAGER` | 200000 – 299999 | Department leads |
| `STAFF` | 300000 – 399999 | Standard department members |

UID namespace mappings are auto-generated by the orchestrator and applied with the kernel's `newuidmap` and `newgidmap` helpers. Cross-department UID collisions are prevented by the orchestrator's UID range allocator.

## Assigning a tier on spawn

Pass the tier as the second argument to `dept spawn`:

```bash
# Headquarters department at ROOT
sudo ./build/ghost-ctl dept spawn headquarters ROOT

# Engineering at MANAGER
sudo ./build/ghost-ctl dept spawn engineering MANAGER

# Finance staff at STAFF
sudo ./build/ghost-ctl dept spawn finance-ops STAFF
```

The orchestrator rejects tier names other than `ROOT`, `DIRECTOR`, `MANAGER`, and `STAFF`. The value is case-sensitive.

## Inspecting the hierarchy

```bash
sudo ./build/ghost-ctl hierarchy show
```

Output renders the four-tier tree with each department's tier, PID, and namespace IDs.

## Verifying enforcement

After spawning a department, confirm the UID mapping is in place:

```bash
sudo cat /proc/<pid>/uid_map
#          0     100000      65536
```

The first column is the in-namespace UID, the second is the host UID, and the third is the range size. A container at `MANAGER` tier with namespace root mapped to host `100000` cannot read files owned by host UID `200000` even if it shares a mount with that department.
